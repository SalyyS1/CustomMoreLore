A Paper addon for MMOItems. Lore is built from MMOItems data and falls back to native output whenever a runtime capability is unavailable.
Paper addon · MMOItems

Item lore, arranged exactly the way your server needs.

CustomMoreLore puts several stats on one line, creates dedicated lore blocks, removes separators when values are missing, and keeps MMOItems as the source of truth.

First layout
layout:
  - '<gray>⚔ #attack-damage# <dark_gray>| <aqua>#attack-speed#'
  - '<yellow>✦ #critical-strike-chance#'
  - '#abilities#'
  - '#lore#'

1. Installation

  1. Put CustomMoreLore.jar in the server's plugins/ directory.
  2. Install MMOItems and MythicLib on the server. PlaceholderAPI is optional.
  3. Start the server once to create config.yml and formats.yml.
  4. Edit plugins/CustomMoreLore/formats.yml, then run /cml reload.
Items without a matching profile, or with an unsupported capability, keep their native lore. The plugin does not modify MMOItems language files, templates, or NBT.

2. Layout DSL

Each entry under layout becomes a line. Plain strings preserve their spacing; use rows and columns when missing values should remove their own separators.

Row with a dynamic separator
- row:
    parts:
      - text: '<gray>⚔ '
      - token: attack-damage
        render: fragment
      - token: attack-speed
        render: value
    join: ' <dark_gray>| '
    absent: remove-part
Compact columns
- columns:
    - token: attack-damage
      render: fragment
      absent: remove
    - token: attack-speed
      render: value
      absent: remove
  gap: ' <dark_gray>| '

Render modes

ModeMeaning
fragmentKeep MMOItems labels, formatting, colors, and locale.
valueUse the raw value so the layout can format it itself.
blockUse for multiline blocks such as abilities, elements, effects, or lore.

3. Profiles and matching order

Profiles are compiled into immutable snapshots. A failed reload never replaces the active snapshot.

PriorityDeclarationExample
1Specific itemprofiles.items.SWORD:sunblade
2Item typeprofiles.types.SWORD
3Defaultprofiles.default
profiles:
  default:
    layout: ['#lore#']
  types:
    SWORD:
      extends: default
      layout:
        - '<gray>⚔ #attack-damage# | #attack-speed#'
  items:
    SWORD:sunblade:
      priority: 100
      layout:
        - '<gold>Sunblade'
        - '#attack-damage#'

extends and parent are both accepted within the same bucket. A higher-priority item profile wins when profiles share a bucket.

4. Tokens and placeholders

MMOItems

#attack-damage#, #attack-speed:value#, #abilities#, #elements#, #effects#, #lore#, #native-lore#.

Placeholders

%player_name% for PlaceholderAPI; {player_name} or [level] for the MythicLib parser.

Viewer-dependent placeholders are available only for /cml preview. Viewer-specific output is never written to a shared ItemStack.

5. Commands and permissions

CommandPurpose
/cml reloadLoad, validate, and activate a new snapshot.
/cml validateValidate the active configuration.
/cml debug itemInspect MMOItems identity, profile, capabilities, and metrics.
/cml preview <profile>Preview in memory for the current viewer.
/cml editor <profile>Open the draft editor, add rows in chat, preview, and save.
/cml reformat hand|inventory|player <name>Write viewer-independent lore back to items.

The admin permission is custommorelore.admin. Individual permissions are custommorelore.reload, validate, debug, preview, editor, and reformat.

6. Compatibility

  • Built against a common API surface for Paper 1.20.x and 1.21.x.
  • MMOItems and MythicLib are server-provided dependencies and are not shaded into the jar.
  • The MMOItems lore hook is synchronous and deprecated; async repair is best-effort.
  • Tooltip items keep native output unless a profile explicitly enables replacement.

7. Troubleshooting

Stats do not appear

Run /cml debug item and check the item type, ID, and stat spelling. Use render: fragment when you want MMOItems formatting.

Separators remain visible

Replace the plain string with a row or columns entry and set absent: remove.

Reload is rejected

Check the server log for the source line. The previous snapshot remains active when the new configuration is invalid.

Preview works but the item does not change

The layout probably contains a viewer-dependent placeholder. Persistent lore only accepts viewer-independent output.
